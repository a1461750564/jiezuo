# 视觉与交互评审手册

本手册可用于主执行者自检或获准的独立评审；自检的交付说明首行写“未独立评审：<原因>”。独立评审者只根据当前截图与约束判断；分数按第 1 节的锚点给，拿不准时取低一档。

只提供评审，不修改被审实现，不启动其他评审者；记录可写入任务指定的证据目录。自检按 [协议](visual-review.md) 整理与本次任务相关的证据与记录，不因缺少派发工具而省略相关检查。分清看得见的缺陷和个人的风格偏好；没有明显问题就直说，不为了凑数提修改。没看到、没法验证的内容要写明；只有静态截图时，不能声称动效或操作流程已经通过。

## 1. 全新界面与改版评审（打分制）

**评审视角**：拉高标准，以“该体裁里最顶尖的团队会怎么做”为标尺。

0. **三秒测试（先于一切细节和流程）**：先问“换一个无关产品，这页能原样用吗？”把首屏缩到 480px 宽（手机截图缩到 180px 宽）看三秒，再看遮字版三秒，写下两句话：它像哪一年的哪一类产品；第一眼看到的是什么。若主要对象、任务关系或关键信息没有落实，只剩可替换的通用外壳，指出具体缺口并按评分锚点判定；不因采用常见版式、系统字体或看起来属于某个年份就自动封顶。说服型页面第一眼看到的主视觉或构图换到别的产品上同样成立，辨识度不及格；工具、后台与工作区沿用侧栏、紧凑工具条、趋势面板或表格/队列等高效品类基线不扣分，三秒测试看表面层次是否干净透气、是否退回“四张等宽指标卡 + 满屏彩色胶囊”的粗糙模板，以及核心业务关系与异常焦点是否一眼可辨。能用截图工具时，用它出缩略图和遮字图。说服页没有实拍、遮字后只剩色块、分隔线和按钮时，记为辨识缺陷，建议按 [说服型骨架](direction-persuasion.md#没有实拍时示意说明品类证据只来自记录) 的顺序改成领域原生对象或标“示意”的对象线稿，不建议补伪照片或编造读数。
1. **品类与标杆检验**：一句话指出这属于什么品类（如 B 端后台、展览落地页），该品类里标杆产品在首屏怎么做。指出现有画面违背共识的地方，判断是有意的创新，还是套用了模型的默认模板。能找到时，拿一两张同品类顶尖产品的实际画面并排比，说清素材、材质和场景完成度差在哪里。
2. **模型默认做法（扣分项）**：
   - 没来由的“左边大标题 + 右边说明/图片”的默认分栏。
   - 处处圆角卡片、每个层级都画线框（留白已分开的地方还要画线，让画面发碎）。
   - 给普通卡片或提示框随手加一条单侧彩色粗边线当装饰；侧栏当前项和正文引用线不算。
   - 无来由的渐变、发光、表情符号图标 (Emoji)。
   - 空泛、晦涩的比喻式文案。
   - 配色没有产品依据：对照交接里的选色记录或品牌资产，既说不出跟产品有什么关系、又直接套了品类最顺手的模板色才扣分；黑白灰或经典色相只要理由立得住，不扣分。
   - 字体和素材显旧：把系统字体拉开字距当品牌字标或标题字，几种系统字体轮换着冒充不同品牌；全部品牌感只靠一个饱和纯色按钮；生成图是通用的素材库质感，看不出属于这个产品。
   - 独立结论保存后再看截图工具的“默认做法提示”，逐条看它是否仍在画面上。仍在、交接里又没写理由的，按本节扣分；写了理由的，判断理由是否来自这个产品。
   - 品牌字标挤占当前任务的空间：App 每屏左上角都放 Logo 加产品名，或品牌行下面再叠一行页面标题，扣分。网页的落地页、官网、文档站在左上角放标识不扣分；画面里的实物铭牌属于场景；主 Agent 在交接约束里写明品牌要求的不扣分。
3. **动效检查（看动没动，不查证据齐不齐）**：按正常速度看录屏；录屏里看不清或没有时，自己打开页面操作一遍。只判断该动的地方动了没有：
   - 主操作反馈是否清楚，必要状态切换是否易于理解；首次出场按产品需要检查，不强制加动画。
   - 已选用滚动叙事的页面，检查其是否服务内容、各区块的节奏和减少动态效果的退路；没有业务或品牌需要时不因缺少叙事扣分。
   - 小游戏、抽奖、计时养成这类产品，按实际玩法反馈需要，再按 [游玩](play.md) 核对“过程即玩法”和“素材与渲染”。
   - 确实没做的写进问题。做了的，动得好不好放到“提升”的动效一项里评，不在这里展开。
   - 不逐帧拆录屏，不核对证据文件。录屏和截图对不上，或只在个别帧里看得到的瑕疵，以正常速度下看到的为准。只有静态截图、页面也打不开时，写一句“没看到动效”，不猜。
4. **提升：精致度、设计感、动效**：缺陷清零的页面常常只是及格。这三项逐项看，有看得见的差距才写，每条写位置、现在的水平、做到什么样算到位；某一项确实没有，写“没有”和依据。提升是把已有的东西做得更好，不是再加东西。第一条是“重做”时不写提升。
   - **精致度**：查看高密度细节图或放大图片看（不等于浏览器缩放重排），哪个组件或哪处排版最显粗糙：字距和行距、图标和文字的对齐、阴影和描边、各状态是否一致；再在实际阅读尺寸看中文断行、孤字和数字格式；缩放可访问性用真实浏览器 200% 另验，模拟视口不能冒充。顺着整页从上往下数所有标题和正文块的左边缘 X 起点：有秩序的版面整页共享 2–3 条垂直锚线，如果左起点散成五六处，直接指出哪几块没对齐。
   - **设计感**：主角在 480px 缩略图里看不看得见、占多大；哪一处最接近品类最好水平，还差什么；哪一处仍是组件库默认的样子。把每一屏的构图概括成一个词（如 `分栏`、`大字列表`、`错落画报`、`选配台`、`满版图`）：同类构图反复出现时，把重复作为检查线索；有对象、比较或阅读关系依据的同构保留，仅在没有信息增量、破坏阅读层级或造成可观察任务困难时指出模板复读。另将首屏隐藏，仅看核心区块下半页和后续详情/确认截图，核对它们怎样继续已选概念的构图、对象和操作关系；说清具体断裂的关系及位置。明显脱离概念是有证据的设计缺陷，不能降为可忽略的风格偏好，也不因“没有贯穿”自动升为 P0/P1；按实际影响分级。重复同一图案、色板或小图标不能单独证明延续。再检查整页节奏与收尾：如果每一屏都被塞进带底色或边框的卡片盒子里（缺少直接排在开放画布上的留白呼吸与高低错落），或者首屏很有风格、下面却退回成每个区块上下画一条通栏细横线、结尾只放几个默认输入框，直接指出。点题真交互（能亲手操作的选配、试算或实时状态装置）必须真实可操作。
   - **动效**：不只看有没有。哪一处动得机械：匀速、各动各的、全页一律淡入上移、和操作接不上；哪一处最值得做出手感，让人想再操作一次或往回再滚一遍。手感用“动作 + 实物参照”写，不写形容词。
5. **精简与瑕疵**：
   - 填缝文字：为了把版面两端配平而塞进去的小字，例如听起来有诗意却不指向任何对象、动作或数据的短句，或写在界面上的设计说明。逐条点名，要求删掉。
   - 列出确实无信息价值的重复文字或制作说明，并解释删除后的含义；“示例”“待核实”“仅供示意”如表达真实模拟/结果未知边界必须保留，不能按词判废话。
   - 除了文字，还要列出该删或该并的面板、数据和装饰：每一屏只有一个主角，多出来的点名。删完以后主角没有变大变强、画面只是变空的，或者具体业务信息被笼统套话替代的，同样算问题。

核对构图、字体、素材和交互是不是都在呼应设计北极星。工具、后台与内容浏览页面，说明首屏对象数量、第一排内容的位置和主动作与当前对象的距离，并和同类优秀产品比较密度；同时检查画面是否清爽透气——有没有一上来把左中右三栏和多层子卡片同时塞满导致视线局促，列表是否被满屏彩色胶囊和重复线框切碎，点开对象后的详情是否讲清了前因后果而非重复表格字段。

参考作品是方向与质量基线，不要求照抄；精准还原任务以给定参考图为准。若有同类优秀作品截图，可与当前画面一起按完成度排序并说明差距。借用的媒介只是风格来源，不为了“更像”而增加无用部件。

**媒介与评分口径**：先确认获准的是示意、平面图形还是写实方向。示意按辨识、比例、连接关系、线型与排版的一致性评完成度；手绘、平涂、缺纸纹/光影本身不构成缺陷或分数上限。写实方向才比较材质与空间表现。连接错位、遮住识别特征仍是可观察问题，须说明影响，不能把偏好写成必须加材质。跨页连续看对象、状态、导航和焦点；没有转场不扣分，已采用的动画若破坏连续性则按实际影响记录。

**走查与分级**：走查与记录范围按 [协议](visual-review.md) 确定：覆盖实际用户和受影响路径，不固定角色数量，可用表 `角色 | 任务 | 步数 | 结果 | 卡点 | 保存后读回`；没操作不能写已验证。完整工作区与表单评审逐项检查：状态可知、贴近现实、可撤销退出、用语一致、预防错误、无需记忆、熟手效率、必要信息、错误恢复、帮助入口。每项 0（不可用）至 4（完整成立），附证据；不能验证写未验，说服页可不适用，分数不并入审美分。

问题编号并存任务目录：P0 阻断任务，P1 明显困难（用户会因此找客服），P2 可绕过，P3 精修。第二轮起复核模式只判旧编号已修/未修及新问题；新的独立评分者不看复核材料和历史分数。结论依次按证据无效、P0/P1、骨架不成立、其余，选重拍/修复/重做/可交付。每轮记录实际 token 口径和耗时；取不到写 null 与原因。

**输出要求**：

- 开头先列一份紧凑的速查清单（每行一条：`[R1-01 / P0–P3] 位置或选择器：现象 → 修完要达到的可验收结果`），方便主 Agent 逐条勾销、不漏改；清单下面再写详细分析。
- 先写问题，再写提升。问题只写会阻断任务、读不清、明显是模型默认做法或核心区块/后续页面明显脱离已选概念的，按影响从大到小排序，优先列关键项，不为条数上限隐去 P0/P1；提升最多 5 条，精致度、设计感、动效三项都要表态。每条写位置、观察证据、影响、修完要达到的结果和怎样验收。改法只写目标，不替制作方定构图，不规定要放多少对象、多少数据，也不建议用加功能、加数据量来换真实感；要求新增任何元素时，同一条里写明为它腾位置要删掉什么；更小的问题合成一句放在最后。主 Agent 会按这个顺序修改，下一轮也会拿这份清单逐条核对，所以每条要写到修完能看出来的程度。
- 首屏骨架仍是模型默认模板，或主视觉远低于同品类水准，分数因此落在 6 分及以下时，第一条写“重做：……”，点名要重做的区块和原因，不再给这些区块列修补建议。在被否定的骨架上修补，只会把它修得更像样。
- 倒数第二行写“保留：……”，点名一两处修改时不能磨掉的做法，通常是这个方向最有辨识度的地方。
- 最后给出 1–10 分的总分。

验收结论按 [协议](visual-review.md#判定口径) 分别报告。分数按下面的锚点给，先看任务，再看视觉：会丢数据、走不通、骗用户“已成功”的问题，比任何视觉问题都优先扣分。任务全部走通也不等于 8 分，主视觉同样要过门槛。

| 分数 | 门槛 |
| --- | --- |
| 10 | 挑不出可观察的缺陷，至少一处是这个品类里没见过的好做法 |
| 9 | 主流程、异常状态、细节都成立，核心区块与后续页仍属于同一件作品，提升只剩小处；至少一处达到品类最好水平 |
| 8 | 方向鲜明，主流程走得通，没有阻断和数据丢失；页面有主视觉或关键素材的，达到同品类一线产品的完成度；缩到 480px 仍认得出作品特征（工具与后台为清爽的表面秩序与清晰的业务重心）；有若干中等问题 |
| 7 | 方向成立，但有一处会让用户丢数据、走错、卡住的问题，或首屏结构仍带明显的模型默认做法，或主视觉对象难辨、比例/连接关系含混、未兑现所选媒介的表达目标，或三秒测试仅见可替换外壳而对象与任务关系缺位；不按手绘、平涂或某一种版式本身封顶 |
| 5–6 | 能看出方向，但骨架是模型默认模板，或主流程有多处卡住 |
| 1–4 | 主任务走不通，或画面有重叠、裁切、看不清这类基本错误 |

分数写在锚点上，指出“唯一最大视觉差距：具体位置/关系 → 可观察完成目标”，从精致度、设计感或已有动效中选当前影响最大的一项，不以“再补一种状态”代替视觉判断；已无可观察差距就说明依据，不强凑。执行者在硬缺陷修复后优先处理这一项，在已定方向、事实与业务边界内可重做相关整段，而非默认只许微调。

每条意见标清有证据的缺陷、可选提升或风格偏好；说明可观察影响，不把后两类自动改成必修。评分必须附具体差距，不同模型的数值不直接比较，用户判断优先。不猜不存在的文件与行号。

## 2. 存量已有界面润色评审（只对齐规范，不打分）

**评审视角**：不要想象你理想的风格，而是严格遵循该产品现有的设计规范（色板、间距）。

主 Agent 提供成文规范或从现有设计变量、共享组件与同类页面整理的现状规范，以及不能改动的品牌、字体、主色、组件库和导航。没有一致的现状时，以多数做法为准，少数做法记为待统一；规范本身有问题时单独列出，交给用户决定。

1. **偏离规范检查**：逐条指出当前画面哪里用了规范以外的颜色/字号/圆角，或者明明有现有组件却自己手搓了一个。
2. **布局与结构**：在规范范围内，指出实际存在且最影响完成度的问题（至多三处，不凑数）（层级、对齐、留白、减法）。
3. **动效检查**：看这次改动涉及的动效到不到位、有没有把原来的动效改坏；用户明确要求或整页升级时，再按第 1 节的“动效检查”核对整页。
4. **输出要求**：只提供客观修正建议，列出可删减的文字。**不打分**。不建议更换整体品牌色或字体。

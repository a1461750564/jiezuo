# 视觉评审与派发协议

按 SKILL.md 步骤 4 选模式。实现由单一写入者完成，评审只读；按当前执行者实际工具分支，不把“有协调者”误当自己能派发。

## 判定口径

| 判定 | 依据 |
| --- | --- |
| 能力覆盖 | 实现、可运行资源和对应证据；维护者逐项记录，不由某一页面分数代替 |
| 任务可用 | 事先约定的任务、数据与授权硬要求，及未解决P0/P1；未验不当通过 |
| 质量与改善 | 手册的具体完成度、缺陷与同条件比较；只给单次评分时不能声称稳定提升 |
| 9分目标 | 单列实际得分与达成情况；低于9分不自动推翻其他三项 |

用户事先指定的质量门槛与轮次优先；8分仅在任务或版本验证明确采用时生效，不是所有任务的默认门槛。结论写清“任务未通过 / 评审未完成 / 质量门未过 / 未达9分目标”中哪些成立。四种处置结论用于决定下一动作，不替代这些验收结论。

## 1. 按改动选择

| 改动 | 方式 |
| --- | --- |
| Pro：新界面、整体改版或说服页选定方向后 | 有隔离且能看图的执行者就默认独立评审，按新界面标准打分；目标 9 分，单次任务最多 3 轮 |
| 存量整理、升级、扩展 | 对照现状规范；同时命中 Pro 行时按 Pro 行，既有品牌与业务约束仍保留 |
| 小改动、仅诊断、用户要求省用量 | 自检并按首行格式说明；仅诊断不修改 |

先应用小改动/诊断/省用量的例外。已定方向的说服页精修仍独立打分；用户另定轮次或一次性验收时服从该限制，不自行追加轮次。

### 派发能力与交接

三种环境均按本次范围整理已有自检证据：相关文件与页面、实际问题及影响、必要的操作走查；多方向比较时再做撞车判定，不同角色存在实质不同路径时再分别走查。完整 Pro 评审保留编号清单、实际用量/耗时和任务目录记录，取不到用量写 null 和原因；小改动自检可简述结果，不补空表、固定角色数或独立报告。复用仍有效的证据；自检不冒充独立评审。

- **能派发**：默认启动隔离且能看图的只读评审，按下面的匿名物料和闭环交接；自检文件不交新评分者。
- **不能派发但有协调者**：交一份 `派审请求`，写原始任务、只读物料的绝对路径/版本/视口、设计与操作约束、评审模式/轮次预算、结果交回位置。只请求一次，不等待或反复催问；先按手册完成自检并交付，首行写“未独立评审：当前执行者无派发工具，已交协调者派审”。
- **两者都没有，或缺少隔离/看图能力**：完成可做的自检，首行写“未独立评审：<具体原因>”，缺失证据照实标明。

协调者收到请求后，核对物料与实际派发能力，按本协议派只读评审；将独立结论及后置 lint 核对结果交回原执行者，逐条标已修/未修/有依据保留并复验。没有能力就明确降级，不能把交接或等待写成闭环通过。新评分者不接收自检清单；复核者可以接收问题清单，两种模式分开。

## 2. 送审前与交接

- 逐项检查桌面/手机等目标视口、首屏/整页/必要状态是否齐全，内容与文件名、版本对应；sticky 截出的空白带、残缺区域、加载失败均先重拍。必要时补真实滚动的分段图，不能把空白整页图当有效证据。
- 给用户原始任务、设计边界、北极星、适用规范与当前截图；长页附必要局部，提供 480/180 缩略图和遮字图。多方向同内容同视口，随机编号，映射另存。复用图注明覆盖版本与范围。
- 评审要打开实际页面时，用本机 HTTP 提供只读物料，不交 `file://`（不少浏览器工具会拦截）：`python3 -m http.server <端口> --bind 127.0.0.1 --directory <任务目录>`，交 `http://127.0.0.1:<端口>/<页面>`。脚本访问本机地址时绕过系统代理（如设 `NO_PROXY=127.0.0.1,localhost`）。仍打不开就写明降级，只按截图评审，不称已走查。
- 不给作者身份、源代码、历史分数、预期排名或自我辩护；新评分者也不接收旧问题和复核结论。先保存独立结论，再提供 `report.json` 的 lint 原文和有依据的保留理由，做第二遍核对。lint 命中不是缺陷判决，第二遍若改判需保留两版及原因。
- 可给只读可重置的地址/录屏走查。真实写入与未知结果不重放；没有实际画面不打视觉分，没有操作证据明确写“未走查”，不能按角色想象充当实测。

### 通用检查

只检查本次受影响的路径，逐项写实际证据与通过/问题/未验证/不适用；不能把清单写进文档就算模型行为已通过。

| 检查 | 取证与判定 |
| --- | --- |
| 中间宽度 | 按 [布局](layout-and-viewport.md#中间宽度) 看相关断点与过渡区；记录对象/主动作、遮挡和留白用途，无溢出不是构图通过 |
| 键盘焦点 | 按 [交互与状态](interaction-and-state.md#电脑手机与键盘) 实测异步前中后与下一步；记录实际焦点、可见性及用户已移开时是否抢焦点 |
| 重复信息 | 按 [逐句减法](detail-and-subtraction.md#逐句删字保留信息再压缩表达) 列事实、位置和用途；报无增量的整组复述，不按次数裁决 |
| 概念延续 | 按 [手册](reviewer-manual.md) 隐藏首屏，仅看核心区块和后续页面截图，说清已选概念如何转成构图/对象/操作关系；明显断裂是设计缺陷，不按个人偏好忽略，也不自动升为P0/P1 |
| 跨页连续 | 按 [交互与状态](interaction-and-state.md#跨页对象与状态连续) 核对对象/状态来源、直达刷新、返回恢复与焦点；转场可不采用 |
| 示意完成度 | 按 [手册](reviewer-manual.md) 区分媒介和缺陷，列出辨识、比例与连接依据；不把纸纹或写实当通用门槛 |

## 3. 每轮闭环

1. 首轮直接独立评审。第二轮起先用复核模式，对持久清单逐条标“已修 / 未修”，另列“新问题”；再换隔离的新评审者独立评分，不传上轮分数、清单或复核结论。评审者不修改实现、不再派评审者。
2. 第一问：“换一个无关产品，这页能原样用吗？”多方向在首屏和整页各做一次两两检查，逐对比较构图、字体、色彩、主角，给“通过 / 撞车”与证据；品牌锁定例外照设计方向处理。
3. 按手册输出编号清单 `R<轮次>-<序号> | P0–P3 | 位置 | 证据/影响 | 验收结果`，存任务目录。跨轮保留编号与状态，不覆盖失败件。P0 阻断任务；P1 明显困难（会因此找客服）；P2 有绕过办法；P3 精修。风格偏好不能冒充 P0/P1。
4. 按实际用户和受影响路径走查，不固定角色数量；涉及不同权限、输入方式或关键使用路径时分别覆盖，可用表 `角色 | 任务 | 步数 | 结果 | 卡点 | 保存后读回`。无保存写“不适用”，未验证照实写。完整工作区/表单评审再使用手册的尼尔森 10 项并逐项 0–4 分，局部精修只检查相关行为；该评分不并入审美分，不据此新增产品角色或审批阶段。
5. 每轮结论四选一，按顺序判断：证据无效 → **重拍**；存在 P0/P1 → **修复**；否则骨架不成立 → **重做**；其余 → **可交付**。重做不自动重开探索，超过授权先报告。可交付不等于达到 9 分；硬缺陷后优先处理手册指出的唯一最大视觉差距及可观察完成目标，在已定方向、事实和业务边界内允许重做相关整段。目标未达可在剩余预算内改进，不能以分数盖过任务失败。
6. 记录交接文件、隔离上下文是否实际使用、独立结论/第二遍 lint 核对、问题状态、撞车/走查结论，以及实际 token 数（注明口径）与耗时。宿主取不到用量写 `null` 和原因，不估算冒充实测。

单一写入者按证据修复并定向复验，再匿名送下一轮。最多 3 轮；预算用完按上述判定口径报告，有关键缺陷明确任务未通过；仅未到9分时写“未达9分目标”，列剩余项并停止。用户规定的一次性验收不在揭盲后改样本或改分。

## 交付记录

交付结果、关键变化、实际验证与限制；取证附实际命令、退出状态和报告路径，未执行或不可用时给具体原因，缺少对应证据则标记取证未完成。只在实际做过时报告动效、轮次与分数，不为填格式追加动作。按 [判定口径](#判定口径) 分开报告能力覆盖、任务可用、质量与改善、9分目标；降级首行沿用本页派发能力分支。设计说明、截图、自检与评审记录均在任务目录，不写入 Skill 安装目录。

评审不能覆盖已定方向、品牌、授权与业务事实。减法保留模拟、估计、待核实、未保存等真实边界；意见冲突以任务与可见证据处理，保留有依据的选择并记录。意见反复且无可见收益时保留最合适版本，明确未解决项并在预算内停止，不通过改分数冒充完成。功能、真实数据和读回失败单独判定。

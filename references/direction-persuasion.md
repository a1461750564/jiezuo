# 说服型页面首屏骨架

落地页、品牌页、产品发布页、展览页等以说服、传递理念为主的页面，按本规范选定首屏骨架（整体设计方向流程见 [设计方向](design-direction.md)）。

先列已有事实、用户要理解的对象关系与主操作，再决定首屏骨架。标题、说明与按钮不能先套进默认分栏；版式应帮助看懂这个产品，而非单靠换色制造差异。

下表是构图工具。每个方向据任务选骨架，用 3–5 个方框说明主次、阅读起点与主操作，并标明各区块帮助识别的对象、理解的关系或作出的判断。对照实际画面核验这些职责：对象已证明的主张，后续说明应补理解、依据或行动；材质与风格表达可因清楚的层级或品牌作用保留。完整取舍见 [说服示范](worked-examples.md#说服页与相关内页)。

| 骨架 | 首屏长什么样 |
| --- | --- |
| 满版图像压字 | 一张图占满首屏，标题和动作压在图的安全区里 |
| 居中单一物件 | 一个物件或一句话居中，四周是大面积空白 |
| 画面即界面 | 首屏就是产品界面或一件实物本身，标题、导航和按钮都长在它上面 |
| 满版文字 | 文字本身就是画面，字大到占满首屏、跨过边缘或被裁切 |
| 通栏上下堆叠 | 通栏大标题横跨整个宽度，下面紧接内容 |
| 网格拼贴 | 多块内容同时出现，按网格或拼贴排列，没有单一主角 |
| 纵排或斜向 | 文字竖排、斜切或旋转，打破从左到右的阅读 |
| 常见组合 | 左文右图或居中标题加卡片可用于主张与证据、总览与选项等真实关系；若只是填空且移到无关产品仍成立，回到对象与任务重排。既有获批骨架按授权保留 |

规则：
- 同一轮比较不同的说服假设与骨架，候选顺序不代表大胆程度；依 [差异检验](design-direction.md#差异检验) 保留有实质差别的方向，不靠加数据、扩大事实或牺牲可用性制造差别。
- 大标题九栏、说明三栏仍是分栏；是否合适看两侧的内容关系，不能只改栏宽就算新方向。
- 固定事实与文案先冻结；组织它们的阅读顺序与主操作，再用骨架承载，不能为造型删改关键内容。

构图的大胆程度和调性无关。安静精致的产品，一样可以把一句话放在空白首屏正中，或让纵排标题贯穿整屏，或让界面本身占满首屏。调性决定音量，骨架决定结构；不以打破版式本身代替产品表达。

首屏露出可直接使用的主操作，并展示只有这个产品能证明的对象、关系或事实。风格承载页面，不能把整屏画成海报、把操作与具体依据赶到下一屏。

窄屏首屏保留主视觉的缩略形态，可裁切、缩放、改成竖排或局部特写，不把对象图形或折页特征整块隐藏；遮住文字后仍能认出品类。按 [布局与视口](layout-and-viewport.md) 取同内容的桌面/手机首屏，同次用 `shoot.mjs --size desktop,phone` 检查丢失提示，再实际看遮字图；检测没有命中不代表已经认得出。

## 没有实拍时：示意说明品类，证据只来自记录

诚实规则管的是证据，不禁止画图。先把首屏图形分成两类：

| 类别 | 回答什么 | 怎么做 |
| --- | --- | --- |
| 说明品类的示意 | 这是哪一行、对象长什么样、已有事实落在对象哪里 | 可以自绘线稿或做成领域实物形态；图上标“示意”，不画修好后的结果、读数或未记录的部件 |
| 事实证据 | 真的发生了什么、结果如何 | 只来自真实照片、截图、记录或读回；没有就写待核实，不用插画、伪照片或带编造数据的截图顶替 |

没有真实素材时，首屏主视觉按顺序选，前一项可行就不往后退：

1. **领域原生对象**：把记录做成这一行真实在用的实物形态，如挂在设备上的检修吊牌、派工单、签收单、交接卡、货运面单、处方笺；只填已有事实。
2. **对象示意**：画出对象和它所处环境的轮廓（设备与连线、车架与部件、货架与库位），标“示意”；把已记录的事实钉在对应部位，实线或实心表示已记录，虚线或空心表示待核实。
3. **领域记号系统**：一套贯穿全页、只属于这一行的记号（工位编号牌、检验印章、管线色标），不是通用图标。
4. **纯文字卡片**：最后手段。在方向说明里写明前三项为什么都不可行，否则不算选定。

对象和记录要连起来：挂绳、引线、同一编号或同一位置标记，让人看出“这张单子属于这台设备”。示意只画轮廓与关系，不追求写实，也不画成扁平剪贴画；线型、字体和颜色跟页面同一套。

示意的完成度看对象可辨、连接关系清楚、比例/线型/排版一致，不能仅因手绘、平涂或没有纸纹、光影就判低一档。已选择写实方向时，才按该方向核对材质与空间可信度；两者都不能用质感掩盖假事实。相关内页检查对象与状态连续，不强制实物化或转场，见 [交互与状态](interaction-and-state.md#跨页对象与状态连续)。中间宽度构图与重复内容分别按 [布局](layout-and-viewport.md#中间宽度)、[逐句减法](detail-and-subtraction.md#逐句删字保留信息再压缩表达) 核对。

自检看遮字图：三秒内说得出“这是哪一行、哪一类对象的记录”（如“会议屏和投屏终端的维修单”）才算过；只说得出“一张卡片、几个色块、一个按钮”，就回到上面的顺序。手机首屏保留同一对象的缩略形态。正例见 [澄明 A 首屏](../assets/prototypes/persuasion/a.html)：会议屏与投屏终端的示意线稿，工单用挂绳挂在终端上，现象钉实心点，供电和信号两处待对照用虚线。

## 从不同说服角度推演整页

先冻结内容、证据与边界，再改变“为什么相信/愿意继续”的论证关系；不是为每个方向换一套数据或发明成功指标。可按任务比较不同角度，例如降低接手成本、解释可核实的过程、直面风险与未知；概念必须落实到阅读顺序、视觉主角和真实动作，不能只写一段方向文案。

| 推演 | 需要改变的具体关系 | 不能改变 |
| --- | --- | --- |
| 对象/使用过程说服 | 先给可理解的对象与操作，再解释价值 | 真实接口、数据、权限和结果状态 |
| 主张/证据说服 | 明确主张，逐步放出依据、限制与行动 | 不能把合成图表当真实业绩 |
| 连续关系说服 | 让同一对象跨区块推进，解释前后因果 | 不能靠滚动劫持、遮挡正文或假动作制造推进 |

选定概念后检查整页映射：首屏的构图/字阶/图形语言如何延续到特性、证据、错误/状态、主动作、FAQ 和页尾；相关内页沿用相同 tokens、导航和状态语义。每一节按信息需要改变节奏，不把所有内容重复套进同样的三卡模块。重塑现有项目仍须在实际代码集成，原型不能替代。

独立运行例见 [澄明三个概念](../assets/prototypes/persuasion/concepts.json)：同一内容分别以可操作交接记录、编辑式主张与案例票据、可核对的日志/连续记录说服；三页首屏以下的区块顺序、标题和页尾也各自不同，`concepts.json` 逐项记录论证、构图、图形、控件与页尾的变化。`a.html` 是完整主方案，`how-it-works.html` 是相关内页；`c.html` 含一镜到底，`a.html` 含轻视差。它们是合成案例，不是官方 Pro 模板。日常候选数量继续按入口和当前请求决定，不因样例有三个就固定三套。

## 同一对象的整页推进

首屏先让人看懂对象、已知事实与当前未知的关系，身份不必抢过故障或观察。离开首屏后，每个需要判断的区块继续让读者知道在说谁；可用共享记录头、连续线或就近引用，不机械重复整条文案。

以具体记录或证据说服时，在桌面与手机的初始视口、不滚动，核对能否直接指出“什么对象、发生了什么、什么仍未知”。只有口号、编号和待核实徽标不算展示了观察。空间不足时把已有观察前移、缩减开场留白或重排层级；不能改固定文案、补造事实，或把关键观察藏到滚动轨迹才出现。实际截首屏核对，不用整页里找得到来代替。

滚动的每一步说明新增了什么、依据来自哪里、哪些仍未核实；同一对象的累计视图保留前文，时间用一致层级。把各步已有事实画出来，不用同样大小的空泛文字框冒充推进。移动端与减少动态效果下仍能顺着读完，阶段间不留失去上下文的长空隙。收尾动作贴近最后的判断，强度与去向清楚；保持既有CTA契约，不为叙事擅改目标。

阶段图形也表达核实程度：已发生、正在处理和未决不能全部画成已完成节点；用文字与线型、形状或填充共同区分，不只换颜色。历史依据与当前新增依据保持可比较的字阶，收尾保留下一动作，不再重复整段开场。

收尾段只写下一步和未决事项，不再完整重列前文依据。

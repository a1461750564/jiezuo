# 表单恢复与浮层选择

适用于录入、批量操作、确认与局部编辑。先核对项目表单库、服务端契约和保存方式；不要为了展示重做字段模型。

从填写到混合结果、修改、查单与回执的完整路径，见 [恢复示范](worked-examples.md#表单恢复)；按当前协议映射状态，不复制业务字段。

## 校验与恢复

1. 标签描述对象，帮助文案只补充格式、限制和后果。客户端校验可即时反馈确定规则；服务端仍是权限、库存、唯一性等约束的权威来源。
   标签与控件实际关联，点击标签也能定位/切换控件；选项标签和控件形成同一命中区。给输入有意义的 `name`，按用途选 `type`、`inputmode` 与 `autocomplete`；不要统一关闭自动填充或拦截粘贴。邮箱、代码等字段按内容关闭拼写检查；placeholder 只补示例，不能代替标签。沿用项目表单组件的既有实现。
2. 确认时展示字段内错误及可定位的错误汇总。提交后将焦点放到第一个错误控件，汇总提供对应定位链接，保留其他输入；不要每输入一个字就抢焦点或连续报警。
3. 异步校验区分“检查中/可用/冲突/检查失败”。只应用与当前值、请求序号相匹配的结果，旧请求不能覆盖新输入。检查失败不等于校验通过。检查结果与状态提示用合适的 `aria-live` 播报，避免每字打断。
4. 请求发出前提交按钮保持可用，点击后校验并说明错误；实际请求中锁住重复入口，给出加载状态。重复点击、按 Enter、录屏/截图都不能意外重发。按钮禁用只是 UI 层，协议有幂等键时继续正确使用。
5. 部分成功后将已确认对象固定为已完成；重试只包含仍失败且已更正的项。保存原对象 ID、错误和草稿，不以重置全表单来“恢复”。
6. 超时/断网发生在发送后，先显示结果待核实；按请求 ID/幂等键读回。pending 时保持等待或允许稍后核实；只有服务端明确可安全重试时才提供写入重试。幂等键不等于可以无限重发。
7. 草稿只保留业务允许的字段，遵守现有隐私与存储约定；不要将凭据存到 localStorage。关闭、返回、刷新及重新进入的恢复入口应明确。明确“保存草稿”与“已提交”的区别；离开有未保存内容时按既有策略提醒，确认放弃才能丢弃。

计数验收：分别读回请求总数、接纳对象及实际写入总数，不能只检查最终数据相同；服务端幂等可能掩盖重复请求。取证工具的重放规则见 [工具](tools.md)。

## 每种结果只讲一次当前决策

填写时字段说明只解释格式/限制；部分成功后就近标出完成项、错误项与应修正的字段；待核实时突出请求身份与查单；完成后把对象、联系人和已确认数量集中在一处可读回的结果。原输入按恢复需要保留，不让库存提示、状态摘要和底部回执反复占据相同注意力。

手机从错误到下一动作、从最后结果到收尾连续走一遍；若必须反复跨过重复说明才找到操作，应合并反馈。减少重复不删未知状态、保存边界或必要依据，不能只缩字号让页面变短。

## 编辑后的状态一起更新

保留服务端结果与当时提交值，另从当前草稿派生呈现状态；不要让“按钮已可补交”与“输入仍像未修正”各自判断。

| 当前事实 | 行内反馈、汇总与动作 |
| --- | --- |
| 服务端拒绝，值未变或仍违反已知规则 | 活动错误与 `aria-invalid` 保留，指出具体字段，不能补交无效值 |
| 已改且通过已知客户端规则，尚未再提交 | 呈现已修改、待补交；清除旧值的活动红框/`aria-invalid`，旧服务端原因如需保留标为上次结果。不能标成已接纳或保证名额 |
| 已接纳 | 只读保留确认值，不进入补交集合 |
| 已发送但结果未知 | 保留请求身份、先查单，不因编辑或超时回到可重发状态 |
| 查单已确认 / 全部已确认 | 及时移除过期查单与调整指令，回执集中列出对象和确认值 |

状态词在草稿、错误汇总、按钮与完成提示中一致，不混用“待处理/待补交”表达同一状态。行、错误汇总、主按钮、查单入口与回执由同一当前状态派生；补交按钮点明对象，避免只说“1项”。实际停在“错误→改成仍无效的值→改成有效草稿→查单完成→补交完成”逐处核对；业务没有的状态不造出来。输入时不抢焦点，异步结果仍只确认匹配的提交值。计数读回规则不变，检查界面不能额外提交。

## 选择容器

| 容器 | 适用 | 不适用/退出 |
| --- | --- | --- |
| 就地编辑 | 一个短字段、上下文足够 | 跨对象长任务不挤在表格小格里 |
| 非模态 popover | 短筛选、补充信息，仍需参考背景 | 不锁背景；Esc/关闭返回触发者；失焦是否关闭按输入丢失风险决定 |
| 抽屉/侧面板 | 对照列表查看/编辑一个对象 | 是否模态取决于需要隔离的任务，不由“从右滑入”决定；手机可转详情屏 |
| 模态 dialog | 明确且短的确认、需要暂时隔离的任务 | 真实焦点约束、可见关闭、Esc（业务允许时）与焦点返回；不能套多层模态 |
| 独立页面 | 多步骤、可分享或需恢复的长任务 | 不为少量字段强制多页；保留返回上下文 |

原生 `<dialog>.showModal()` 可提供模态语义与焦点约束；组件库按实际版本用其 API。标题与描述要关联，初始焦点按内容/风险选择，破坏操作不能默认焦点到确认。关闭过程中有未提交输入时遵守既有草稿/放弃语义，不能无声清空。浮层不得把后面的主操作和错误遮住。

完整可运行例：[form-recovery.html](../assets/prototypes/form-recovery.html)。客户端错误、异步冲突、服务端部分成功、提交待核实与读回、Esc/焦点返回分别验证；一个 happy path 不代表这些分支都通过。

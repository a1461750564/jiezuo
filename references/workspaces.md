# 按对象和任务选择工作区

先确定反复处理的对象、主要操作、关系与使用频率。W01–W10 是本项目独立分类；选择主骨架，再按需要组合次级区域，不用“左侧栏 + KPI 卡墙”替代信息架构。

| ID / 骨架 | 信息关系与主操作 | 不适用 | 可运行例中的操作 |
| --- | --- | --- | --- |
| W01 队列 | 按优先级/到达顺序逐项处理；待办 → 当前项 → 结果 | 需要同时对比许多字段 | 搜索维修项、处理、保留查询返回 |
| W02 表格 | 同构对象的列比较、排序、选择与批处理 | 强空间关系、主要内容是长文 | 筛选、选择行、批量标记并读回 |
| W03 主从详情 | 在对象间来回查看详细上下文 | 一项漫长任务需要持续独立工作 | 选择、详情、窄屏返回保留位置 |
| W04 看板 | 对象在有限阶段间流转，关注瓶颈与在制品 | 状态不允许自由移动、精密列比较 | 用按钮将任务推进至下个允许阶段 |
| W05 日程 | 时间/资源冲突是核心，定位可用时段 | 日期只是一个普通属性 | 选日期、预约时段并显示占用 |
| W06 编辑器 | 持续创作一个对象，工具服务内容与草稿 | 大批量审核、主要任务是浏览 | 编辑、保存、本地草稿恢复 |
| W07 画布 | 直接操纵位置/尺寸，空间本身承载意义 | 仅为了炫技把普通列表画成节点 | 选择元素、按钮/方向键移动、保存读回 |
| W08 图关系 | 节点之间的依赖、路径或影响比坐标更重要 | 简单层级目录、无意义装饰连线 | 选择节点查看上下游与影响 |
| W09 监控 | 时间序列、异常与新事件驱动行动 | 普通经营报表没有实时处理需求 | 暂停流、查看事件、继续；标清更新时间 |
| W10 检索分析 | 问题 → 条件 → 证据结果 → 解释/下钻 | 操作流程已固定的逐项任务 | 查询、过滤结果、展开证据来源 |

原型入口：[workspaces.html](../assets/prototypes/workspaces.html)。十个模式共用 tokens 与外壳，内部结构和主动作各自不同；是可改编的最小骨架，不是十个完整产品或真实业务后端。

完整路径与取舍见 [队列/详情示范](worked-examples.md#队列与详情)：从定位到返回，解释为什么优先保留有效结构。

## 从首屏贯穿到结果

- 用真实长度的标题、ID、状态和错误来定密度，先做最常走的“定位 → 查看 → 处理 → 返回”。主操作不能在详情页退回另一套按钮、字阶或状态语义。
- 在同一工作区中持续保留筛选、选中对象、详情、反馈、次级操作与页尾的信息层级；主题、边框、图标笔触和状态含义从共用 tokens 来，不逐屏即兴决定。
- 队列突出下一步与对象；表格用列、对齐和批操作栏；图/画布提供文字等价入口与键盘路径；监控暂停不应伪装成数据仍在实时更新。
- 电脑主从与手机两屏共享对象与返回语义。固定工具栏不能遮挡最后一行、错误或焦点。长页实际滚到收尾。
- 选择一个主骨架的理由应能指向任务成本。若改造流程，先读 [旧项目改造](existing-project.md)，冻结可改范围和保护契约。

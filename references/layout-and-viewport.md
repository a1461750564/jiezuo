# 布局与视口

## 精准还原

先记下参考图对应的视口尺寸或已知的像素尺寸、画面的完整范围，以及哪些区域是固定不动的。图片的像素数不等于视口尺寸，例如 2 倍图要除以 2；确定不了时，写明你是按什么假设的。

量出主要区域各占多大比例、哪些元素共用一条对齐线、文字多大、图片怎么裁、各处间距之间是什么关系。先把整体的位置、比例和字体对上，再处理边框、阴影和细节；还原任务不重新探索风格。

用和参考图一样的视口、差不多的内容来比差异。参考图里没有的窄屏和其他状态，按内容的需要补上，并标明哪些是照着参考还原的，哪些是自己合理延伸的。

自己判断还原得像不像，结论通常偏乐观；只看一张整页缩略图，也看不出字号、间距和对齐差了多少。每轮修改后用截图工具的 `--compare` 出对比图（见 [工具](tools.md)），先修差异最大的那几格，再在叠加图里核对对齐线、字号和图片裁切；不凭印象宣布“已经还原”。

## 验证重点

实际看一遍内容很长、内容为空，以及这次改动涉及的各个状态。手机上留意视口高度的变化、弹出的键盘和屏幕的安全边距，主操作不能被键盘或固定的栏挡住。

说服页的窄屏首屏保留主视觉的缩略形态：裁切、缩放、竖排或局部特写均可，不整块隐藏，也不缩到接近零或推到下一屏；遮住文字后仍应认出品类。同内容、同状态的桌面/手机首屏一起取证，用 `--size desktop,phone`；只取一个视口时，不能声称已检查跨视口主视觉。重新绘制的手机替代图也要看图确认，DOM 对应不上时自动提示不作缺陷判决。桌面首屏本来就没有达到阈值的图形对象时，输出“首屏图形”说明并在 `heroComparison.note` 留记录；它不是 lint 命中，说服页据此回到 [说服型骨架](direction-persuasion.md#没有实拍时示意说明品类证据只来自记录) 的顺序核对，工具页可忽略。

再检查：页面有没有意外地横向溢出，滚动是不是发生在该滚的那一块，焦点和菜单看不看得见；放大或重新排版以后，阅读和操作的顺序是否还清楚。

## 中间宽度

不只拍桌面和手机两个端点。对本次改动涉及的断点两侧与中间过渡各看实际画面；例如首屏在 1024–1280 之间换布局，就检查 1024、1180、1280，而不是把这三个数固定给所有项目。记录实际 CSS 视口、主对象/主动作位置、遮挡和裁切、留白用途；没有横向溢出不等于构图成立。

保留有意的非对称与留白。内容因旧 `max-width`、定位或分栏残留挤在一侧，另一侧空白又无阅读或操作用途时才报问题；对象叠放若遮住识别特征、正文或操作，也要点出受损部分。拖动窗口找到问题区间，再在受影响宽度留图；不以强制居中或铺满修掉所有留白。

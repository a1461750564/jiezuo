# 青岫器材：从草稿到回执

这是使用合成领用数据制作的教学副本，不连接真实库存。来源哈希与教学改动见 [SOURCE.json](SOURCE.json)；本副本没有独立评分。

## 任务与保护契约

陆汀领三脚架3件、领夹话筒7件、防风罩2件。初次响应为已接纳/数量受限/待核实三种结果。话筒最多4件、改为3件；防风罩先查原请求。固定ID、数量与接口不为排版改变。目标不是清空错误，而是让用户明确现在可以做什么。

## 从状态到界面

[app.js](app.js)中的items保留送出值与服务端结果，current从当前草稿派生呈现状态，render让行内反馈、错误汇总、主按钮与回执一起更新。有效未补交的草稿清除旧红框，但不叫已接纳；已接纳只读、未知保留requestId。最后集中回执，旧填写说明退出。

## 完整路径

[index.html](index.html) → 提交三项 → 看到混合结果 → 数量改0（不得写入）→ 改3（已修改待补交）→ 核实防风罩 → 仅补交领夹话筒 → 回执读到3/3/2。顺序也可先补交再查单，已接纳或pending不能被重新发送。键盘路径与触屏路径表达同一状态。

[server.mjs](server.mjs)是内存假后端；/api/counters分开给posts/writes/readbacks，预期完整主路径2POST、3项写入、1次查单。计数核对和截图共用同一流程，不能为了拍状态反复提交。重启服务器清空演示数据；页面刷新不提供草稿持久化，未知缺requestId时没有自动重试，不冒称覆盖所有恢复分支。

## 取舍与不适用

成熟原生字段和明确状态比新增装饰更重要。表单按决策分区，完成回执接管注意力，必要边界仍保留。业务若是单项提交，不应硬造三种结果；真实服务的幂等、权限、库存和恢复契约必须沿用项目实现。

## 运行与证据

使用已有 Node 在本目录运行 `node server.mjs`，打开首行的127.0.0.1地址/index.html。无依赖安装、业务写入仅发生在本次内存假后端；仅结束自己启动的PID。按上述完整路径核对计数、反馈、键盘和多端布局；私有历史检查资料不随包分发，不作为当前宿主的验收结果。
